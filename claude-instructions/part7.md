### 2026-11-20 — Sprint 29.1: passwords for manager and dev sign-in

**Migration 036 + server + frontend (small-functions sprint).**
- **Why it needed a database:** manager (admin) passwords were plain entries in `server/config/admins.json` (baked into the deploy) and the dev password a hash in the environment (`DEV_PASSWORD_HASH`) — neither could change from the app. They now live in `login_accounts` (`server/accounts.js`).
- **1. Manager can change their own password:** Settings → Account → **Change password** (current + new + confirm; 8–128 characters, no edge spaces, different from the current; Show passwords toggle). `POST /api/account/password` checks the current password; wrong guesses are limited (5 per 15 min per account → 429); success is audited without the password. A wrong current password is a plain **400** (never 401 — the client signs the person out on a 401). Other sessions of that account stay valid until their 8 h token ends.
- **2. Dev manages managers — Dev → Admins** (new dev nav page, key icon): list (name, @username, Active / Switched off, when the password was last set), **Add a manager** (username 3–40 letters / numbers / . _ -, name, password; Generate makes a readable 14-character one), **Reset** a password, **Switch off / on**, **Rename**, and **Show password** (decrypted from the vault copy — same AES-GCM vault + `PIN_VIEW_KEY` as staff PINs; hides itself after 20 s, has Copy). Every add / reset / show / switch is written to `audit_logs` (who + which account, **never the password**). Without `PIN_VIEW_KEY` on the server nothing viewable is stored: the page says so and Reset still works. Admin tokens and dev-only routes: `requireRole('dev')`, `Cache-Control: no-store`.
- **3. Dev can change their own password:** the same card in Settings → Account and on Dev → Admins. Until dev changes it, sign-in uses `DEV_PASSWORD_HASH`; the first change creates the dev row, after which **only the new password works** (no reversible copy of the dev password exists). **Lost dev password:** `DELETE FROM login_accounts WHERE kind = 'dev';` brings the environment password back.
- **How the move happens (nothing to copy by hand):** the migration only creates the table. The `admins.json` admin(s) are copied into it the first time they sign in (or when dev opens Dev → Admins); from then on the database password is the only one that works for that person (the file's no longer does, even though it's still in the file). Until migration 036 is applied, sign-in keeps working from `admins.json` / `DEV_PASSWORD_HASH` and changing a password says "not available yet". Username rules (3–40) apply to NEW admins; the table accepts any existing name.
- **Security notes to remember:** showing a password needs a reversible copy, which is a real trade-off (a leaked `PIN_VIEW_KEY` + database would expose manager passwords). It is dev-only, logged and optional — **Reset is the safer habit**, and removing `PIN_VIEW_KEY` from the server turns the feature off. A switched-off or reset account's already-issued tokens run to their 8 h expiry (no per-request lookup, by design). `admins.json` still contains the original admin password in plain text — **change that password in the app once, then it's dead** (the file value stops working); ideally remove the entry from the file later.
- **Not built (ask if wanted):** a "Change password" link on the sign-in screen itself (needs username + current password, no session), email / forgot-password reset, deleting an admin (switch off instead), forcing everyone out when a password changes.
Tests: new `accounts` (14: the module on a real throwaway Postgres — migration applies twice and is additive, password / username rules, first-use import of the file admin, change password incl. old password dead in DB and file, rate limit, dev env→DB switch + recovery, dev manages admins, reveal with / without vault, behaviour before migration 036 — and the HTTP routes: dev-only 401 / 403 matrix, add / reveal / reset / switch off audited without passwords, admin and dev change-own-password with 400-not-401), new `accounts-ui` (9: the card's rules and messages, Settings → Account for admin and dev, the Dev → Admins page); `devshell` updated (Admins nav). Full regression green (every suite exits 0); lint clean; build compiles.
